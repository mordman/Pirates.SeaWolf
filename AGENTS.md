# AGENTS.md — память проекта Pirates.SeaWolf для LLM-агентов

Этот файл — точка входа для любой LLM, которая продолжает разработку этого репозитория. Здесь: что за проект, как он устроен, что уже сделано (задачи 1–80), как проверять изменения и какие уроки выучены. Порядок чтения для нового агента: **README.md** (краткое описание для людей) → этот файл → **worklog.md** (полный журнал задач с деталями реализации) → при необходимости `git log` (коммиты «Task N: …» содержат самодостаточные итоги).

## 1. Что это за проект

Морская 3D-игра-песочница «Pirates.SeaWolf»: парусники XVII века, бесконечное море, бой, торговля, экипаж. Всё написано на TypeScript: игра — three.js (процедурная генерация кораблей, людей, островов, воды — без внешних 3D-моделей), обёртка — Next.js 16 (App Router), UI — React + Tailwind + shadcn/ui. Разработка ведётся агентом внутри песочницы z.ai (см. раздел 10), игра целиком клиентская; Prisma/`db/` — неиспользуемый шаблон БД (таблицы User/Post пусты).

Ключевая особенность проекта: **всё генерируется процедурно из кода** — корпуса по шпангоутам, дощатая обшивка с разрушением, парусное вооружение (кливера/топселя/латинские), экипаж (простые и детальные модели моряков/солдат/пиратов XVII века), острова с растительностью и животными, звук — синтез Web Audio. Внешних ассетов почти нет (текстуры — `src/game/assets/textures.ts` + несколько картинок в `public/`).

## 2. Быстрый старт

```bash
npm install
npm run dev        # next dev -p 3000, лог в dev.log
# открыть http://localhost:3000 — стартовый экран → «Начать»
```

Проверка кода: `npx tsc --noEmit` и `npm run lint` — оба должны быть чистыми перед коммитом (это правило соблюдалось во всех задачах). Продакшен-сборка: `npm run build`. Сборка БД не нужна, но скрипты есть: `npm run db:push|db:generate|db:migrate|db:reset` (шаблон).

Управление в игре (для e2e и ручной проверки): WASD — руль/паруса, мышь — камера/прицел, колёсико — зум, Tab — карта, H — помощь, P — пушечные порты, 1/2/3 — сабля/пистолет/подзорная труба (в режиме высадки), ПКМ с трубой — осмотр с зумом 2×–8×.

## 4. Как проверяется работа (E2E-система)

Регрессия — скрипты `scripts/e2e_v*.mjs` (Node, один файл на версию, номер = номеру задачи/пакета). Схема прогона: поднятый dev-сервер на `localhost:3000` → скрипт открывает страницу через **agent-browser** (headless-браузер), управляет игрой (клики/клавиши/`window.__game`), снимает скриншоты, проверяет числовые инварианты, а визуальные моменты сверяет VLM-моделью (z-ai vision) по скриншотам. Итог печатается построчно: `A…G: OK/FAIL`, финал `ALL OK (N/N)`.

Запуск: `node scripts/e2e_v80.mjs` (сервер должен работать). Полезные утилиты: `agent-browser close && agent-browser open http://localhost:3000` — рестарт демона браузера (он периодически падает; если e2e виснет — первым делом перезапустить демон и прогнать повторно). VLM-проверка одной картинки: `z-ai vision -p "промпт" -i файл.png`.

Статус регрессий после Task 86: **e2e_v85 — 15/15 ALL OK (абордаж на полигоне), e2e_v82 — 15/15 ALL OK, e2e_v77 — 28/28 ALL OK, e2e_v80 — 22/22 ALL OK, e2e_v78/v65/v67 — ALL OK; e2e_v81 — 21/23** (B3/B4 — тайминг-флейки замера скорости при медленном fps, физика тяги по мачтам не менялась; лучший одиночный результат за историю прогона). v82/v80 в сессии Task 86 не гонялись (SwiftShader-троттлинг песочницы — окружение, не код; долг Task 84 в силе).

## 7. Дисциплина и соглашения

- **Коммит** — «Task N: суть» на русском, подробно (что + корень бага + как проверено + статус регрессий). Мелкие платёжки — `chore:`/`worklog:`.
- **Worklog** — после каждой задачи запись в `worklog.md`: формат ранних задач `Task ID: N / Agent / Task / Work Log / Stage Summary`, поздних — `## Task N — ЗАГОЛОВОК (дата)`. Писать и «что», и «почему» (корни багов) — это главная память проекта.
- **Проверка** — перед коммитом: `tsc` чист, `lint` чист, e2e-прогон ALL OK (новый скрипт `e2e_vN.mjs` на пакет правок), скриншоты ключевых сцен в `download/taskN/`.
- **Не коммитить**: `dev.log`, `scripts/shots/` (локальные скриншоты), `skills/tool-results/`, `node_modules`, `.z-ai-config`. `.env` в git намеренно (в нём только `DATABASE_URL=file:` — путь к SQLite, секретов нет).
- **Язык** — русский: UI, коммиты, worklog, документация. Имена в коде — английские.

## 9. Подводные камни (выученные уроки)

- **Рангоут**: сегменты мачты считаются от базы: `seg2.y = base + j2`, не `j2 − j1` (Task 80 — «парус режет нос при полных парусах» висел так месяцами). Внутренний кливер `setAt=1` ставится ТОЛЬКО при полных парусах.
- **Палуба/корпус**: порядок треугольников решает направление нормалей — палуба вверх (иначе вода «внутри корпуса»); днище замкнуто; материалы DoubleSide.
- **GLSL**: `patch` — зарезервированное слово; нельзя называть так varying-переменные.
- **Floating origin**: мировые координаты ≠ координаты сцены; матрицы дул/орудий пересчитывать через кватернион корабля.
- **Пробитие бортов**: считать по ЛОКАЛЬНОЙ стороне корабля (sideOpen ≥ 45% → снаряд насквозь), иначе «не тот борт ломается».
- **Синхронизация физики и визуала воды**: одна функция Gerstner для TS и шейдера (`waves.ts`) — иначе корабль «проваливается» в волну.
- **E2E**: демон agent-browser периодически падает — при зависании прогона рестартовать демона и повторить; число проверок в прогоне фиксировать в коммите («22 ALL OK»).
- **Песочница перезапускается**: процессы (dev-сервер, браузер) умирают, файлы остаются; после рестарта: поднять `npm run dev`, проверить `curl localhost:3000`, при сбоях — `git status` (права файлов могут «поехать» — было в Task 36/51).

## 10. Среда разработки (песочница z.ai)

Проект разрабатывается агентом в изолированной Linux-песочнице. Конвенции каталогов: `upload/` — входные файлы игрока (не менять), `download/taskN/` — артефакты задач для игрока, `scripts/` — скрипты агента (e2e, аудиты, `devdaemon.py` — автоподъём dev-сервера), `skills/` — инструкции (раздел 8). Команды среды: `z-ai function -n web_search -a '{"query":"…"}'` — веб-поиск, `z-ai vision …` — VLM по картинке; флаги и авторизация уже настроены. Скриншоты e2e складываются в `scripts/shots/` (в git не идут), итоговые — в `download/taskN/`.
